# VK analytics service

Сервис на FastAPI и gRPC: получает доступные через VK API показатели профиля и сообщества и отслеживает изменения онлайн-статуса добавленных пользователей. HTTP используется для управления списком, данные аналитики отдаются по gRPC.

## Запуск

Требуется Python 3.11+ и токен VK с доступом к нужным методам и данным (в зависимости от типа токена и настроек приватности VK). Не добавляйте токен в репозиторий.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export VK_TOKEN='ваш_токен'
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

HTTP-документация: `/docs`. Добавить пользователя: `POST /tracked-users` с `{"user_id": 123}` (числовой VK ID); удалить: `DELETE /tracked-users/123`. Добавление идемпотентно, удаление также удаляет историю. `/health` показывает, что HTTP-процесс работает, но не проверяет доступность VK.

Переменные окружения: `VK_TOKEN`, `VK_API_VERSION` (по умолчанию `5.199`), `VK_DATABASE` (`vk_service.db`), `VK_POLL_INTERVAL` (секунды, `30`), `VK_REQUEST_TIMEOUT` (`10`), `VK_GRPC_HOST` (`0.0.0.0`), `VK_GRPC_PORT` (`50051`). Токен передаётся только на сервер VK. Без него сервис запускается, но запросы к VK и опрос работать не будут.

## gRPC

Контракт — `proto/vk.proto`, сгенерированные Python-файлы — `app/grpc/`. `GetUser` и `GetGroup` запрашивают актуальные поля VK, `ListTrackedUsers` возвращает состояние и время последней проверки (поля отсутствуют до первого успешного опроса), `GetOnlineHistory` — начальное наблюдение и последующие изменения, новые первыми; limit по умолчанию 100, максимум 1000. Идентификатор профиля/группы может быть числовым или коротким именем VK. Доступность полей определяется VK API и приватностью; недоступные счетчики возвращаются как 0.

В указанном [репозитории proto](https://github.com/flexicky/protos) на момент реализации есть только `auth.Auth`, контракта VK нет. Поэтому VK-контракт определён локально и не является частью общего репозитория. Для обновления сгенерированного кода:

```bash
python -m grpc_tools.protoc -I proto --python_out=app/grpc --grpc_python_out=app/grpc proto/vk.proto
# В app/grpc/vk_pb2_grpc.py заменить import vk_pb2 на from app.grpc import vk_pb2
```

## Устройство и ограничения

`app/main.py` управляет жизненным циклом и HTTP, `services/tracker.py` — фоновым опросом, `infrastructure/` — VK API и SQLite, `grpc/server.py` — адаптером gRPC. Опрос происходит батчами до 1000 пользователей с интервалом после завершения предыдущего цикла. Это **не поток событий в реальном времени**: короткие переходы между опросами могут быть пропущены, а ошибки VK задерживают обновление. Неактивные или недоступные профили не помечаются автоматически офлайн. При ошибке батч повторится в следующем цикле. История сохраняется в SQLite между перезапусками.

Запускайте один экземпляр/один worker Uvicorn на базу: иначе опросы дублируются и gRPC-порт конфликтует. Для production необходимы авторизация и TLS для HTTP/gRPC, управление секретами, ограничение запросов, мониторинг, политика хранения истории и механизм распределения задач при масштабировании. Не публикуйте текущие незащищённые порты в интернет. Соблюдайте правила VK и применимые требования к приватности при отслеживании пользователей.

Тесты: `pip install pytest pytest-asyncio && pytest -q` (VK API заменён тестовым клиентом).
